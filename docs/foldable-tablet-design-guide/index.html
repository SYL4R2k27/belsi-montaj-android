01Принципы адаптивности

5 правил, которые определяют как BELSI должен выглядеть на любом Android-устройстве — от Z Flip closed до Tab S10 Ultra.

1. Думаем «классами окон», а не «моделями устройств»

Один и тот же телефон в портрете и ландшафте — два разных размера. Z Fold открытый ≈ маленький планшет, закрытый ≈ узкий телефон. Привязываемся к Material 3 Window Size Class (COMPACT / MEDIUM / EXPANDED) — а не к Build.MODEL.

2. Контент не растягивается бесконтрольно

На EXPANDED (≥840dp) одноколонный текст превращается в нечитаемое полотно. Решение — widthIn(max = 900.dp) с центрированием для контента-чтения, или multi-pane (list-detail) для управленческих экранов.

3. Навигация переезжает: Bottom → Rail → Drawer

COMPACT — BottomNavigation внизу. MEDIUM/EXPANDED — NavigationRail слева. На очень больших планшетах (≥1240dp) — постоянный NavigationDrawer. Material 3 NavigationSuiteScaffold делает это автоматически.

4. Foldable — это не только размер, но и поза

Z Fold можно держать как книгу (вертикальная складка), на столе как ноутбук (TableTop posture), полусогнутым. API WindowInfoTracker сообщает позу — для фото-камеры BELSI используем TableTop (телефон на столе, экран как монитор).

5. Тестируем на эмуляторах из списка ниже, не «на своем телефоне»

Если разработчик тестирует только на Pixel 7 — Z Fold open и Tab S9 у него никогда не работают. Минимальный набор для CI/тест-чек-листа — 6 эмуляторов: phone-compact / phone-landscape / fold-closed / fold-open / tab-medium / tab-large.

03Postures (положения foldable)

API androidx.window.layout.FoldingFeature сообщает положение шарнира. Используется когда поведение зависит не только от размера, но и от того как устройство сложено.

📱
Closed
Полностью сложено, активен только cover-экран
📖
Book (Flat)
Полностью разложено, шарнир вертикально
💻
TableTop
Горизонтальная складка ~90°, верх как монитор
📐
HalfOpened
~90° по любой оси, переходное состояние

Применение в BELSI

  • CameraScreen: при TableTop posture (горизонтальная складка) — верхняя половина экрана = превью камеры, нижняя половина = кнопки. Удобно когда телефон стоит на объекте как штатив.
  • ShiftScreen: при Book (Flat, ширина ≥ 840dp) — две колонки (статус + фото-лента).
  • CuratorPhotosScreen: при Book — list-detail (грид + preview).
  • Closed: cover-экран Z Fold ≈ обычный compact phone — отдельный UX не нужен, работает стандартный.
WindowInfoTracker требует androidx.window:window:1.3.0+. Сейчас BELSI 1.2.0 — нужно бампнуть для polnoponi posture-API.

10Layout patterns

5 шаблонов раскладки, которые покрывают все BELSI-сценарии. Каждый паттерн привязан к конкретному WSC.

A. One Pane (compact)

Single column

Для: телефон portrait, Z Fold closed, Z Flip open. Навигация — BottomNavigation. Контент — одной колонкой во всю ширину.

B. NavRail + One Pane (medium / phone landscape)

RAIL
Single column

Для: Tab S6 Lite portrait, phone landscape, Z Fold open portrait. Боковая навигация + одна колонка. Используется когда у нас 4+ табов навигации.

C. List–Detail (expanded)

RAIL
List
Detail (выбранный элемент)

Для: Z Fold open landscape, 11" планшеты landscape. Idiomatic для управленческих экранов: список слева, детали выбранного справа. BELSI: CuratorMainScreen Tab «Тикеты», «Фото», «Бригады», «Люди».

D. Three Pane (xlarge)

DRAWER
List
Detail
Inspector / actions

Для: 13"+ планшеты (Tab S Ultra, MatePad Pro 13.2"). Список + детали + панель действий/инспектора. BELSI: куратор-аналитика с charts.

E. Centered max-width (любой expanded для контента-чтения)

Контент max 720 dp по центру

Для: формы регистрации, Update Gate, About, Privacy/TOS. Колонка контента ограничена 720 dp и центрирована — текст читается комфортно даже на 1232 dp Tab S10 Ultra.

На широких экранах текст не должен растягиваться на 1000 dp в одну строку. Ограничение длины строки + увеличение размеров шрифта.

Length cap: одна строка текста-абзаца не должна быть шире 72ch (~ 720 dp при body medium). Чтение страдает после этой границы.

// Класс окна

when (windowSize) {
    WindowWidthSizeClass.COMPACT  -> // < 600 dp

// Удобные хелперы

Box(modifier = Modifier.fillMaxSize()) {
    Column(
        modifier = Modifier

        // content
    }
}

19Анти-паттерны

Что НЕ делать — типичные ошибки которые ломают адаптив.

❌ Hardcoded .width(400.dp) на основном контенте

На Z Flip cover (340 dp) контент выезжает; на Tab S Ultra — занимает 1/3 экрана с пустотой. Замена: fillMaxWidth(0.7f) или widthIn(min=320.dp, max=720.dp).

❌ Проверка Build.MODEL == "SM-F946B"

Привязка к моделям ломается на новых девайсах и не работает в эмуляторе. Замена: WindowWidthSizeClass.

❌ Один абсолютный порог screenWidthDp >= 540

540 dp выбран произвольно; на Tab S6 Lite (800 dp portrait) уже надо что-то делать, а 540 не срабатывает. Замена: три порога (600 / 840 / 1240) через WindowWidthSizeClass.

❌ Игнорирование landscape

Если приложение работает только portrait — мобильные планшеты + Z Fold open landscape не получают своего UX. Замена: убрать android:screenOrientation="portrait" в манифесте, поддерживать landscape хотя бы для tablets.

❌ Текстовый абзац шириной 1200 dp

Длинная строка нечитаема (глаз теряет место при возврате на новую строку). Замена: widthIn(max = 720.dp) для текстовых блоков.

❌ Dialog с usePlatformDefaultWidth = false и fillMaxWidth()

На широком экране — диалог во всю ширину 1232 dp. Замена: widthIn(max = 560.dp) (Material 3 maximum для диалогов).

❌ Грид с GridCells.Fixed(2)

На Tab S Ultra (1232 dp) 2 столбца — каждый по 600 dp, нечитаемо. Замена: GridCells.Adaptive(minSize = 320.dp) — сам подберёт количество.
